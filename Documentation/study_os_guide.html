1. What it is

Study OS is a folder of rules, skills, scripts and agents. It helps one person learn a hard topic from zero. An AI agent runs it. The harness keeps every prompt, reasoning step, action and deliverable in its trajectory.

Rules

Short files in .rules/. They bind every answer.

Skills

Task recipes in skills/. Four phases plus a misc group.

Scripts

Python in skills/scripts/. Same input, same output.

Trajectory

The harness records the whole run. skills/self_improve/ distills it into skill fixes.

Four ideas hold it together. Output is HTML only 5. Every claim is cited and scored 1 to 5. Text stays short. Logs are separate from deliverables.

2. Quick start

  1. Get the folder. Copy it to your machine. Keep Artifacts/ and user-input-learning-text/ private. Both are in .gitignore.
  2. Open it in Copilot CLI or the Copilot app. The agent must start in the folder root.
  3. Tell the agent to read the map. AGENTS.md and REPO_MAP.md say where everything is. .github/copilot-instructions.md points to both.
  4. Put your source in user-input-learning-text/. A case file, a book, a transcript. The agent reads it. It never edits it.
  5. Start phase 1. Type /interviewer. Then ask for the map. The agent builds an interactive HTML mind map.
  6. Check the repo map after any change. This guide lives in Documentation/, apart from your deliverables.
python skills/scripts/repo_map.py
python skills/scripts/repo_map.py --check   # must print OK

You need Python 3. The mind map builder and the trajectory distiller use only the standard library. PDF export needs WeasyPrint and is off by default.

3. How the harness works

Three layers. The agent does the work. Rules and skills tell it how. The harness trajectory records the whole run, reasoning and tool calls, for the self-improving loop. See .rules/harness-and-memory.md.

→

→

the loop closes

The trajectory, not hooks

The old session hooks are removed. They only logged prompts and tool calls, never the model's reasoning. The DeepSeek Harness (deepseek-ai/deepseek-harness) already records the whole run as a replayable trajectory: every reasoning step, every tool call, every result 4.

Memory has three levels: the trajectory (raw, per run), claude-mem (thedotmack/claude-mem, optional runtime recall across sessions), and llm_wiki/ (the curated knowledge that compounds). See .rules/harness-and-memory.md.

5. How to extend it

Misc holds tools that do not belong to one phase. Use /skill_creator. It follows .rules/skill-authoring.md.

  1. Say what the skill does and the words you will use to call it.
  2. The agent picks a snake_case name and the folder skills/misc/<name>/.
  3. It writes SKILL.md: front matter, then short steps.
  4. It runs the validator, then 2 or 3 test prompts.
  5. It regenerates the repo map.
---
name: my_skill
description: >-
  misc skill. what it does in one sentence.
  use when the user says phrase one, phrase two, or /my_skill.
model: inherit
effort: medium
---
  • Name: snake_case. Same as the folder name.
  • Description: always a >- block with trigger words. Under 1024 characters 5.
  • model and effort are Claude Code fields 5. Effort: low, medium, high, xhigh, max 5.
  • Fork when the work is noisy or must be independent. A forked skill sees none of your chat, so its text must stand alone 5. Do not fork a skill that needs your chat.
  • Side effects: add disable-model-invocation: true 5. Show a plan first.
  • Keep the body under 500 lines 5.
python skills/scripts/validate_skill.py skills/misc/my_skill

The open spec uses hyphens in names 5. To upload a skill to claude.ai, rename it first.

Put it in skills/phase_N/skills/<name>/. Same format. Name the input file and the output file in the body. Add the file to the phase PATHS.md. Phase skills read the earlier phase's output, so keep the file names stable.

The self-improvement pass turns a finished run into skill fixes. No hooks: the harness trajectory already holds the reasoning and the tool calls.

  1. In the harness, open the run's Trajectory tab and choose Download session log. Save it under Artifacts/sessions/<...>/trajectory.json.
  2. Run the distiller. It writes all-reasoning HTML and a machine list.
  3. Read the gaps against the skill the run followed. Write reasoning_gaps.html. File each gap to skill_factory/feedback.md.
  4. Email both files when you want them (set up once per skills/self_improve/trajectory_distill/references/email-setup.md).
python skills/self_improve/trajectory_distill/scripts/distill.py Artifacts/sessions/<...>/trajectory.json out/
python skills/scripts/send_notes_email.py --subject "trajectory distill" --body "all, then gaps" out/reasoning_all.html out/reasoning_gaps.html

The credential for the email lives only in the env file, never in the repo or the chat 5. Full steps: /trajectory_distill.

Add one short file to .rules/. One topic. Numbered lines. Say the source and its score. Then add a pointer line in AGENTS.md and run the repo map. Rules beat skill text when they disagree.

6. Use cases

How to use the four phases

Phase 1: enough to study. The interactive mind map shows what you must know. Learn each node alone, or with AI help.
Phase 1 prompts feed phase 2. Each node carries a ready prompt. Paste it into a chatbot to carry on. This costs fewer AI credits than running phase 2 inside the agent.
Phase 2: your final note. Write it after you wrestle with the material and force it into your head. You may run it in one shot. Our advice: go slow. Run one phase at a time. Do not run the whole process at once.
Phase 3: exam and advisor. It tests you and names your weak spots.
Phase 4: logs. It files your session logs and finds the root of repeated misses.

Common jobs

Learn a topic from zero

Example: audit a cloud case with no cloud background. Drop the case in user-input-learning-text/. Run phase 1 for a map. Study from the map. Move to phase 2 only for the notes you want to keep.

Learn from a book, video or course

Run the extraction intake first, then map_maker in book or video mode. The map adapts to the mode. It does not copy the audit layout point for point. Examples are in map_maker/references/examples/.

Review how you work with the AI

Run /learn_from_sessions every week or so. It reads the harness trajectory exports and writes a short report in Artifacts/artifacts/. It suggests new skills or changes to old ones.

Learn from an expert's logs

If an experienced colleague agrees in writing, their trajectory exports can show how they steer the AI. You then rebuild their result as a study topic. Follow WORKFLOW_EXPERT_CAPTURE.md. The consent gate is not optional: opt-in, alias only, redaction, no use in performance reviews. The capture skill is not built yet.

Keep the folder clean

Run /tidy. Related topics share a group folder via _groups.json, for example ten AWS topics under one case name.

Make your own skill

Run /skill_creator. See section 5.

Repo map check failsRun python skills/scripts/repo_map.py. Then --check.
